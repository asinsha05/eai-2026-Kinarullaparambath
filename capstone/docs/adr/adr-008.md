# ADR-008 — Three dedup layers: the client Idempotency-Key, the saga business key, and the provider keys

**Status:** accepted
**Date:** 2026-11-20

## Context

The same order can arrive twice in three different ways, and each needs a different answer. A client times out and retries. A customer submits the same order again with a new key. The orchestrator retries a payment call after a timeout, when the provider may already have charged.

## Decision

Layer 1, intake (`intake/src/server.ts`, `idem` store): the same Idempotency-Key and the same body bytes get the same stored answer and the same correlationId, with no second event. A different body gets 409. Layer 2, the saga (`orchestrator/src/server.ts`): the business key `${source}:${orderId}` under a different correlationId makes the second order `duplicate` with `duplicateOf`, and no step runs. Layer 3, the providers: payment and inventory calls carry `authorize:<businessKey>`, `reserve:<businessKey>`, `refund:` and `release:` keys, so the retry of the first step after an unknown outcome produces one charge. Notices are different: the notification provider has no key, so the notifier dedupes on correlationId in `processed-ids.json`, and a notice can still be sent twice if the provider sent it but our call failed. A second notice is an annoyance; a second charge is real money.

## Alternatives considered

- One layer only, the provider keys: a duplicate order would still reach the providers and the customer. Rejected.
- A unique constraint in a database: databases are not allowed in this project.
- Deriving the correlationId from the business key: it would hide a genuinely new attempt. Rejected.

## Consequences

Each layer catches a failure the others cannot: layer 1 the client retry (same key), layer 2 the resubmission under a new key, layer 3 the half-finished provider call. A customer who orders again after a decline with the same orderId gets `duplicate`, and has to use a new orderId; that is an accepted cost. The stores are JSON files, so every check reads memory but every write rewrites a file.
