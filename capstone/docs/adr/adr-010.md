# ADR-010 — A saga that lost its orchestrator becomes needs_attention and is never resumed automatically

**Status:** accepted
**Date:** 2026-11-20

## Context

If the orchestrator dies between two steps, we do not know whether the interrupted call took effect. Re-running a step could charge twice or create a second shipment, and shipping and notification have no idempotency key.

## Decision

At every start the orchestrator draws a new run id (`RUN_ID`). Each saga record stores the run id that owns it, or `retry` while it waits in the retry path. When a message arrives for a saga that has no outcome and whose owner is neither this run nor `retry`, `markStuck()` moves it to `needs_attention`, publishes `order.needs_attention` and runs nothing. Because the message stays unacked until the saga ends, RabbitMQ redelivers it when the restarted orchestrator connects, so detection is immediate; the SAGA_STUCK_AFTER_MS variable is not used. `GET /sagas/stuck` lists `needs_attention` and `compensation_failed`. `POST /sagas/:cid/compensate` runs the compensations of the completed steps that are not yet done, in reverse order: `inventory_release`, then `payment_refund` (a b2b order has no payment, so only the release). It is idempotent once finished and answers 409 while one is running.

## Alternatives considered

- Resuming from the last completed step: needs to know whether the interrupted step took effect, which we cannot. Rejected.
- Compensating automatically: could refund an order whose shipment already left. Rejected.
- Temporal: its event history records exactly which activities completed, so stuck sagas would not exist; we did not build that component, and `/sagas/stuck` would answer an empty list in that mode.

## Consequences

False positive: a saga that had finished every step but not yet persisted its outcome is marked stuck, and an operator may compensate an order that was in fact complete. Before pressing compensate an operator must check the mocks' `/admin/effects`: the shipment and the customer notice are never undone. The cost of this design is a human in the loop for every crash.
